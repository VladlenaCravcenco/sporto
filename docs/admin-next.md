# Админка в Next.js

## Что перенесено

`/admin/login` — отдельный вход email/пароль. `/admin` — прежний dashboard.
Разделы: products, brands, categories, attributes, featured, import, requests,
clients, banners, contacts, popup, faq, services, maintenance, content-pages.
`/admin/content` перенаправляет на content-pages. Сохранён дополнительный
read-only список истории `/admin/requests/history?client=<uuid>`.

Редакторы переиспользованы как динамически загружаемые Client Components.
Next отвечает за маршруты и серверную авторизацию; адаптер React Router
сохраняет навигацию существующих редакторов. Это функциональный перенос,
а не переписывание всех форм на Server Actions.

## Сессия и доступ

Сервер принимает admin email из `ADMIN_EMAIL`, затем `VITE_ADMIN_LOGIN_EMAIL`,
затем `VITE_ADMIN_EMAIL`. Без значения доступ закрыт. Email сравнивается без
учёта регистра; пароль проверяет Supabase Auth. Локальный sporto_admin_ok
не является условием доступа в Next. Supabase Auth сохраняет сессию в cookies,
общих для Next и перенесённых редакторов.

REST и Storage запросы редакторов проходят `/api/admin/supabase/...` с повторной
проверкой администратора. Подмена Authorization в браузере не меняет пользователя:
сервер использует проверенную cookie-сессию. Межсайтовые изменения блокируются.
RLS применяется с токеном пользователя, без service-role и без изменений БД.
Realtime продолжает подключаться к Supabase с пользовательской сессией и зависит от RLS.
Оставшиеся вопросы live RLS из старого аудита требуют отдельной проверки.

## Развёртывание

Из корня проекта: `bash scripts/deploy-host.sh`.
Затем открыть `http://217.26.149.55/admin/login` и войти прежним email/паролем администратора.
Google и смена DNS для этого не нужны. Данные те же, что у старого сайта;
сохранение в редакторах изменяет общую базу.

Gateway допускает тело до 25 МБ; лимит Nginx также должен позволять нужный
размер (`client_max_body_size`). HTTP 413 при загрузке требует проверки этого
лимита. Существующие отсутствующие Storage buckets, например brand-banners,
не создаются автоматически. Ошибки доступа должны устраняться в конкретной
политике, а не открытием публичной записи.

## Проверки

- `npm run next:build`: production build и TypeScript.
- `node scripts/tests/admin-access.cjs`: анонимный/обычный пользователь,
  admin identity, вход, CSRF, маршрутизация запросов, user-token RLS,
  передача JSON и бинарной загрузки. Все внешние вызовы подменены.
- `node scripts/tests/checkout-form.cjs` и `categories-store.cjs`: регрессия общего кода.
- Локальный запуск сервера не выполнен: пользователь отклонил разрешение.
- Реальная проверка входа, CRUD, импорта, экспорта и Storage на сервере ещё не выполнена.

После деплоя: войти, открыть каждый раздел, сохранить согласованную правку товара,
загрузить изображение, обработать заявку, проверить историю клиента, выйти и
убедиться, что повторное открытие `/admin/products` возвращает на вход.
