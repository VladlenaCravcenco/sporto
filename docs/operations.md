# Поддержка SPORTO

## Сервер

Ubuntu, Nginx и systemd-сервис `sporto` на `217.26.149.55`. Приложение слушает локальный порт 3000. Основной адрес — `https://www.sporto.md`; остальные варианты перенаправляются на него.

Исходная конфигурация: `/var/www/sporto/.env.local`. Релизы: `/var/www/sporto-releases/`. Не копируйте секреты в репозиторий.

```bash
bash scripts/check-domain-host.sh
bash scripts/check-order-host.sh
```

Администратор определяется на сервере через `ADMIN_EMAIL` с совместимостью `VITE_ADMIN_LOGIN_EMAIL` / `VITE_ADMIN_EMAIL`. Запросы админки проходят серверную проверку и Supabase RLS.

## Сертификат и DNS

Сертификат Let's Encrypt для `sporto.md` и `www.sporto.md` продлевается через webroot и `certbot.timer`.

```bash
bash scripts/enable-certificate-renewal-host.sh
```

При изменении DNS сохраняйте записи подтверждения Google и почтового домена Resend. Адреса страниц, canonical и sitemap должны использовать `https://www.sporto.md`.

## Откат

Деплой хранит текущий и предыдущий исправный релиз. Если новая версия не проходит проверки запуска, каталога или поиска, скрипт восстанавливает предыдущую конфигурацию сервиса. Для ручного восстановления сначала проверьте `systemctl cat sporto` и `previous-release.conf` нужного релиза.

Резервные копии конфигурации домена и продления находятся в `/var/backups/sporto-domain/` и `/var/backups/sporto-renewal/`. Используйте путь конкретной копии, выведенный соответствующим скриптом.

Исторические SQL-скрипты и их проверки вынесены в отдельный архив вне проекта. Объединения товаров имеют приватные резервные копии в `sporto_product_merge_backups`. Для отката нужен проверенный скрипт под текущее состояние базы; объединения откатываются от новых к старым.

## Товары и SEO

Защита SKU установлена в базе: триггеры `sporto_products_sku_guard` и `sporto_products_sku_release`, приватный реестр `sporto_product_sku_reservations`. Существующие повторяющиеся SKU разрешены при редактировании прежних карточек, новое назначение занятого SKU запрещено.

Объединённые карточки остаются в базе неактивными. `product_redirects` хранит старые ссылки, `product_category_links` — дополнительные категории основной карточки. Не удаляйте эти таблицы вручную.

Публичные страницы должны отвечать 200, иметь canonical и быть доступны роботам. Удалённые товары без замены возвращают 404; объединённые — постоянное перенаправление на основную карточку. Админка, аккаунт и корзина не индексируются. Проверка опубликованных страниц:

```bash
python3 scripts/tests/page-seo-http.py --base-url https://www.sporto.md
```
