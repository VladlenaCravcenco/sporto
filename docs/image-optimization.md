# Изображения

Общий StoreImage выбирает размер через srcset/sizes для карточек, меню, подсказок поиска, баннера, главного фото товара и миниатюр.

Обрабатываются публичные JPG/PNG/WebP/AVIF по стандартным адресам *.supabase.co/storage/v1/object/public/. Supabase выполняет resize/форматирование, Next.js не декодирует изображения на хостинге. Используется ограниченный набор размеров, quality=80 и contain без обрезки. SVG, GIF, локальные файлы, подписанные ссылки и внешние сайты остаются как есть. При ошибке трансформации компонент один раз переключается на оригинал.

Требуется платный Supabase с включёнными Image Transformations. Они учитываются в лимитах/стоимости проекта: https://supabase.com/docs/guides/storage/serving/image-transformations

Скрытые баннеры не получают img до первого показа. Первое изображение баннера и главное фото товара загружаются с высоким приоритетом; карточки и миниатюры — отложенно. Пропорции контейнеров сохранены.

SQL не нужен. Публикация: bash scripts/deploy-host.sh на Mac из проекта.

После публикации в Network браузера проверьте изображения на мобильном экране: для файлов Supabase должен выбираться /storage/v1/render/image/public/ с width. Сравните transferred bytes с оригиналом при отключённом browser cache. Если появляется ошибка трансформации и запрос оригинала, проверьте включение Image Transformations в Supabase. Экономия на рабочих фотографиях пока не измерена. Изображения поставщиков этим изменением не уменьшаются.
