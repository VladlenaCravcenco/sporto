## 1. Категории и подкатегории — высокий приоритет

Фактические страницы: `/ro/catalog?category=aparate-cardio` и `/ru/catalog?category=aparate-cardio`; подкатегория добавляет `subcategory=banda-alergat`.

Подтверждено HTTP:

- HTTP 200; title, description и H1 остаются общими для всего каталога.
- Robots: `noindex, follow` для категорий и подкатегорий.
- Canonical сохраняет category/subcategory; hreflang использует правильные `/ro` и `/ru`.
- Неизвестная категория возвращает 200 и noindex. Для фильтра это допустимое отдельное решение; для будущей самостоятельной посадочной неизвестный slug должен давать настоящий 404.

Подтверждено кодом:

- Любой query, кроме page/sort, включает noindex (`app/[lang]/catalog/page.tsx`).
- Меню и главная ведут на эти фильтрованные URL. Отдельных маршрутов категорий нет.
- Из БД загружаются локализованные описания категорий, но каталог не использует их как основной текст выбранной категории.

Следствие: сейчас нет индексируемых посадочных под запросы конкретных товарных групп. Параметрический URL сам по себе не является ошибкой; проблема в noindex, общем содержимом и отсутствии самостоятельной SEO-политики.

Работы:

1. Выделить категории/подкатегории как посадочные, с постоянной структурой URL и стабильным идентификатором из БД. Пример структуры для согласования реализации: `/[lang]/catalog/[category]/[subcategory]`; это пока не существующий маршрут.
2. Сохранить noindex для поиска и комбинаций дополнительных фильтров; отдельно определить canonical сортировки, пагинации и фильтров внутри посадочной.
3. Серверно формировать название группы в H1, уникальные title/description, короткое вступление, товары, ссылки на подкатегории, breadcrumbs.
4. Добавить только существующие индексируемые посадочные в sitemap и заменить ссылки меню/главной.
5. Старые category/subcategory URL нормализовать с сохранением полезных фильтров и языка; не перенаправлять произвольные комбинации вслепую.
6. Проверить неизвестные slug, соответствие подкатегории родителю, отсутствующие переводы, пустые группы и страницы за пределами пагинации.

## 2. Бренды — высокий приоритет

HTTP `/ro/brands/insportline` и `/ru/brands/insportline`:

- 200; title только `SPORTO`, description только `SPORTOSFERA S.R.L.`.
- Нет canonical, hreflang и H1 бренда в полученном HTML.
- Имеющийся блок JSON-LD принадлежит общему layout/breadcrumbs; его наличие не доказывает наличие полноценной разметки бренда.
- Неизвестный бренд также отдаёт 200 с теми же общими metadata.

Причины в коде:

- Catch-all не проверяет наличие бренда на сервере и не экспортирует generateMetadata.
- `BrandPage` получает бренд через useEffect; серверный render начинается с spinner.
- При логотипе вместо имени рендерится только img: после загрузки у обычной страницы бренда также отсутствует H1.
- При неизвестном бренде рисуется надпись 404, но статус HTTP не меняется.
- Товары раскрываются кнопкой «Показать больше» без самостоятельных URL пагинации.
- SeoHead после загрузки использует старый canonical `/brands/...` и query hreflang, а не текущие локализованные маршруты.
- Бренды исключены из sitemap.

Работы: серверная загрузка активного бренда; notFound для неизвестного/неактивного; SSR описания и первой страницы товаров; generateMetadata; постоянный H1 независимо от логотипа; доступная ссылками пагинация; согласованная политика брендов без товаров; sitemap активных индексируемых брендов. Сохранить визуальный дизайн и клиентские интерактивные элементы.

## 3. Информационные страницы — высокий приоритет

Проверены About, Contacts, TurnkeySolutions, MaintenanceService, TermsOfCooperation, DeliveryTerms, PrivacyPolicy в двух языках.

На всех 14 ответах:

- HTTP 200; присутствуют H1 и статический контент. Нельзя утверждать, что Client Components автоматически лишают эти страницы серверного HTML.
- Два title: корневой `SPORTO` и заголовок legacy Helmet.
- Два description: корневой `SPORTOSFERA S.R.L.` и описание страницы.
- Canonical указывает на старый URL без языка; RO и RU имеют один и тот же canonical.
- Hreflang указывает на старые `?lang=ro`/`?lang=ru`, а sitemap — на `/ro/...` и `/ru/...`. Это противоречивые сигналы.
- Robots legacy-компонента явно выставляет index,follow. Staging-защита HTTP-заголовком должна проверяться отдельно.

Источники контента:

- About имеет встроенный основной текст, FAQ обновляется через useEffect.
- Turnkey/Maintenance используют встроенные defaults; редакторские значения приходят через клиентские hooks после первоначального render.
- Terms/Delivery/Privacy первоначально используют встроенную версию; опубликованный редакторский контент загружается через usePageContent/useEffect.
- Наличие текста в HTML не подтверждает, что это актуальный текст из админки. Сходимость initial HTML и опубликованного контента нужно исправить и проверить отдельным сравнением.

Работы: серверные metadata всех семи страниц; отключить legacy Helmet именно в Next-пути при сохранении Vite-совместимости; canonical и взаимные alternates на текущие URL; серверный initial load опубликованных текстов и FAQ, передача данных в существующие UI; актуальные контакты и достоверная JSON-LD.

Редакционные замечания: H1 контактов «Станьте нашим партнёром» не поясняет назначение страницы; H1 услуг рекламные, без названия услуги. Это рекомендация улучшить ясность, не формальная ошибка HTML. Утверждения о бесплатном проекте, официальном дистрибьюторе, гарантии и происхождении оборудования надо сверить с реальными условиями, а не распространять шаблон на все товары и бренды.

## 4. Общие замечания

- Legacy WebSite SearchAction указывает `/catalog?q=...`, текущий поиск использует `/[lang]/catalog?search=...`. Исправить или удалить неактуальное действие.
- Информационные страницы уже включены в sitemap, но их canonical не совпадает с URL sitemap.
- sitemap отсутствием брендов/категорий не запрещает индексацию, однако в сочетании с отсутствующим SSR брендов и noindex категорий структура для продвижения неполна.
- Не следует добавлять schema ради обещания роста позиций. Разметка должна соответствовать видимому содержимому; FAQ rich results и прочие расширенные результаты не гарантированы.
- Доступность фактического текста и стабильных страниц полезна для поиска и ИИ-ответов; результаты и цитирование не гарантированы.

## Порядок исправления и критерии приёмки

1. Информационные страницы: устранить конфликт metadata и URL, обеспечить актуальный серверный текст. На каждом URL ровно один title/description/canonical; canonical совпадает с текущим языком, взаимные hreflang ведут на существующие страницы.
2. Бренды: полноценные серверные страницы и HTTP 404 неизвестных брендов; H1, описание и товары доступны без JavaScript; пагинация доступна ссылками.
3. Категории: индексируемые посадочные с локализованным содержимым; фильтры остаются контролируемыми; URL, меню, canonical и sitemap согласованы.
4. Повторить матрицу RO/RU на production build и staging, проверить отсутствие повторных metadata после hydration и HTTP-заголовки. После домена — Search Console URL Inspection, индексируемость и sitemap.
